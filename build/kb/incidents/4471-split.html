  • parser: the shared parser reads every date month first, and every tenant on file writes the day first. “Booked for 2 July. The invite says 7 February.” Fix: parse in the tenant’s locale.
  • hint: the booking-v3 form prints MM/DD/YYYY under its date field. People type month first, as told, and the form reads the date day first. The parser fix does not touch it. Fix: print the hint from the tenant’s locale.
  • shift: the date moves by one day, not by a swap. “Client in Lisbon got Tuesday. Client in Toronto got Monday. Same meeting.” That is timezone handling, not parsing. Fix: keep booking dates as calendar dates, not midnight instants.

How a report is placed

  1. One id, one report. The export repeats some ids across overlapping pages; each counts once.
  2. shift: the reports the desk itself read as a one-day move (desk-notes.json). No day/month swap fits any of them.
  3. hint and parser: by tenant, as causes.ts already does. A day-first tenant’s report through the booking-v3 form is hint; any other report from a day-first tenant is parser.

Intake’s tag is a guess from the reporter’s browser. The column above shows how often it disagrees with the tenant; the tenant decides.

  • The #4471 cause table already showed hint as a second cause and footnoted the one-day moves inside parser. The page above it said “one issue”, so neither got a ticket.
